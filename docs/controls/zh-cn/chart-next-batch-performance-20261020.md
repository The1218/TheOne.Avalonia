## 环境与方法

- macOS / Apple M4、.NET 10、Avalonia 12.1.4、Release；前后使用本轮开始时的工作区基线与各优化路径的冻结构建，未使用旧 Git 提交替代工作区基线。既有预览页测量完成后，只调整新增图表；其性能数据与最终新图表构建分别记录程序集身份。
- 真实桌面使用 Avalonia.Native 窗口与同一 1100×820 视口、同一 OneTheme。每种页面一个新进程冷样本，随后 20 次重新创建页面。耗时从页面构造开始到首个 RAF 回调，包含挂载和布局；**RAF 回调不等于 GPU 绘制完成**。
- p50 为中位数（偶数样本取中间两项平均）；p95 为 nearest-rank，第 `ceil(0.95×n)` 项。冷样本 n=1，不计算冷 p95。分配为 UI 线程托管分配，不包含原生／GPU 内存。
- 新图表离屏绘制使用 Avalonia.Headless + Skia；其 CPU 时间不能与原生桌面 RAF 直接比较，也不能换算为真实帧率。
- 原始样本、专项探针、程序集绝对路径与 SHA-256 放在 `.preview/chart-next-batch-20261020/`，不加入正式启动入口；显式二进制引用和哈希核对防止测到旧程序集。

## 既有预览页：打开卡顿

| 页面 | 冷首开，前→后 ms，n=1 | 重复打开 p50，前→后 ms | 重复打开 p95，前→后 ms | 首布局分配中位数，前→后 MiB |
| --- | ---: | ---: | ---: | ---: |
| Gauge | 922.17 → 370.45 | 150.08 → 65.04 | 250.17 → 80.68 | 9.85 → 2.70 |
| Line | 677.41 → 463.56 | 181.27 → 83.27 | 244.67 → 108.91 | 9.69 → 3.72 |
| Scatter | 786.46 → 578.34 | 185.54 → 108.11 | 238.03 → 151.41 | 9.69 → 3.72 |

p95 分别减少约 68%、55%、36%。改善成立于当前宿主和视口，未宣称页面打开已达到单帧预算；冷启动仍含主题、JIT、模板和文字系统初始化。

主要瓶颈是立即创建屏幕外的代码高亮区和控件树。分解测量中，两个带高亮代码的 Description 行挂载／布局约 100.91 ms、6.80 MB；同样内容使用普通文字约 1.43 ms、24 KB。这是定位数据，不是将演示降级为纯文本的方案。

实施方式：保留全部带名称的样式对比网格；第一幅图立即创建，其余样式、动画说明和高亮代码按真实 EffectiveViewport 创建。内容物化后使用自然高度，不继续强制占位高度；不靠 Dispatcher 延后同样工作。图表样本使用独立系列包装，图例状态不串用；Gauge 不再创建不使用的 ViewModel／Series／Point。

首次布局可视控件数 Gauge 271→52，Line / Scatter 261→109；已创建的高亮编辑器均由 2→0。滚动后全部示例和高亮代码仍可访问。首次进入高亮编辑器区域仍承担其初始化成本；窗口足够大、内容本就在视口内时会正常立即创建。

## 新图表性能

统计图输入 1,000 条观察；层级图输入 10,000 个节点，640×420 离屏绘制。预热 15 次后记录 80 次缓存重绘，包含实际 Skia 绘制上下文提交，不只是几何准备。单点更新项为设置一个点的 Y 并准备目标几何，n=1，**不包含随后的光栅绘制，不是更新 p95**。

### 两种统计图的首次基线

| 控件，1,000 条 | 缓存重绘 p50 / p95 ms | 托管分配 KiB／次重绘 | 单点更新与几何准备 ms，n=1 | 单点更新分配 MiB |
| --- | ---: | ---: | ---: | ---: |
| BoxPlot | 15.08 / 18.16 | 28.14 | 7.80 | 1.00 |
| Candlestick | 13.71 / 16.15 | 26.31 | 10.05 | 0.96 |

两者没有旧版同种控件，以上仅为首版基线，不能称为对旧版的速度提升。数据来自 `stats-performance-final/metrics.json`。

### 层级标签缓存前后

前版为新图表初始实现，后版为增加最多 16,384 个节点的文字测量缓存、精确的无空间标签预检及文字画刷一致性处理后的版本。单点权重变化保留投影、节点和集合订阅；新字体、主题、文字、显式 Foreground 和可变画刷改变时正确失效。

| 控件，10,000 节点 | 缓存重绘 p50，前→后 ms | 缓存重绘 p95，前→后 ms | 单点更新与几何准备，前→后 ms，n=1 | 更新分配，前→后 MiB |
| --- | ---: | ---: | ---: | ---: |
| Treemap | 11.36 → 5.68 | 14.14 → 6.93 | 143.96 → 10.07 | 27.15 → 0.081 |
| Sunburst | 33.91 → 36.39 | 37.70 → 56.34 | 211.16 → 55.26 | 34.25 → 7.30 |

**Sunburst 未获得稳定的缓存重绘尾延迟改善。** 为检查顺序和运行时波动，另按后版→前版顺序重复同一 80 帧脚本：后版 p50 / p95 为 32.47 / 40.97 ms，前版为 99.82 / 162.07 ms；该次单点更新为后版 38.23 ms、前版 387.47 ms。两次数据均保留，不能只选择有利的一组宣称绘制加速。更一致的结果是更新分配从约 34.25 MiB 降到 7.30 MiB，减少约 78.7%；万节点扇区的路径创建和光栅尾延迟仍是瓶颈。

原始 80 帧样本、前后程序集 SHA、顺序分别见 `tree-performance-before/`、`tree-performance-after/`、`tree-performance-before-run2/`、`tree-performance-after-run2/` 及本地 `VALIDATION.md`。既有预览优化后库 SHA 前缀 `c3573e9a`；最终新图表库为 `db7d65e4`，新图表追加修复未改变上述三个既有页面的构造路径。

缓存重绘不重新枚举源数据，单点更新不重建全部数据订阅；统计图仍重算范围／布局，层级权重更新仍需生成受影响几何。以上不表示 O(1) 全帧更新或万节点 Sunburst 已满足实时帧率。

## 专项验证范围

只验证新增四种图表、受影响的预览创建路径及共享订阅／导航的 Line、Heatmap 最小调用方。未运行全控件回归。

已覆盖：统计值顺序与缺口、离群集合替换及共享引用、Median / Close 与 Y 的通知一致性及单次失效、选择／命中／视口、层级 Reset / Replace / ItemsSource 替换、唯一 Key 回退、循环和重复引用、Root 清理、卸载重挂、目标帧 PNG、动画开关、Light / Dark × 三档尺寸和窄视口。

首轮四图专项 123 项；最终统计专项 57 项、层级专项 114 项、统计锚点／离群动画预算及 Heatmap 公共调用方 7 项，原生预览路径专项 91 项，均通过。它们存在重叠，不相加为唯一用例数。最终构建 0 错误，保留原有 LoginDemoViewModel 可空告警，未扩展修改范围。

真实鼠标／键盘覆盖两种统计图的选择、缩放与平移，以及两种层级图的双击下钻、返回和键盘选择。预览滚动、窄视口、三档尺寸及卸载重挂检查确保所有延迟区域最终物化，未以丢弃内容获得性能改善。

当前宿主实跑不代表 Windows / Linux 实跑通过；未进行本轮 NativeAOT 发布、GPU 调用栈或全控件回归。万节点 Sunburst 光栅耗时及极深树的祖先画刷查找仍有后续优化空间。
